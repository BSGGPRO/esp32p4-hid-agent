# 图片 → 笔画 → 板子画出来（image-to-draw）

> 目的：用户丢进来一张图（照片/线稿/截图/图标），程序把它转成「一串折线笔画」，
> 再由 ESP32-P4 的 HID 鼠标在 Windows 画图里一笔一笔画出来。
>
> **不依赖模型看图**：整条链路是确定性图像算法（阈值/细化/追踪/简化），
> 模型不需要"看见"图也能画。质量用数值指标（pearson / ink IoU）自检，
> 最终像不像由用户/能看图的模型判断。

## 1. 两个工具

| 工具 | 作用 |
|---|---|
| `tools/ingest-image.py` | 任意来源/格式 → 统一 PNG：`--clipboard` 读剪贴板、路径读任意格式、`--latest` 取 inbox 最新、`--thumb N` 出缩略图。SVG 用 Edge headless 光栅化；HEIC/PDF 给明确提示 |
| `tools/draw-image.py` | 图片 → 笔画规划（line / sketch / grid）→ 预览 PNG + plan JSON → 可选 `--draw` 真画 |

## 2. 三种描线策略

| 模式 | 适合 | 做法 |
|---|---|---|
| `line` | 线稿 / 简笔画 / 卡通 / logo / 签名 | 灰度阈值 → Zhang-Suen 细化成 1px 骨架 → 方向连续性追踪成折线 → RDP 简化 |
| `sketch` | 照片 / 复杂图（铅笔速写风） | 高斯模糊 + Sobel 边缘 → 细化 → 追踪 |
| `grid` | 小图标 / 像素风 | 原分辨率判墨 → 按格子统计 → 暗格子点一个点 |

关键修复（2026-10-18）：8 连通骨架的斜线会产生"台阶"（度数=3 的伪分叉），
按"度数≠2 就断"会把一条线切成一堆 2px 碎片（实测 2373 段）；改成
**方向连续性走法**（没走过的邻居里挑方向变化最小的、对角优先）后变成 85 段，
简化后 26 笔 —— 这是画得出来的前提。

## 3. 画的时候怎么保证不跑偏

* 每笔起笔用 `brain.locate(tol=1)` **闭环**落到起点；
* 落笔后按实测增益表（`pointer_profile` 的 `gain_table`）把「像素位移」反算成 count，
  开环快速推进（约 10px/步，1 条约 12ms）；
* 每 N 个顶点读一次 `GetCursorPos()` 做**周期闭环校正**，偏差 > 1px 就补一步；
* 偏差 > 40px 判定用户抢鼠标：抬笔、跳过该笔、记录事件（不把用户的乱动画进画里）；
* 每笔开始前复核前台窗口必须是画图，否则停手。

速度：cat 线稿 26 笔 / 193 顶点 ≈ 4 秒；sketch 42 笔 / 492 顶点 ≈ 7 秒。

## 4. 怎么验证「像不像」（没有眼睛也能查）

`draw-image.py` 会把原图按同比例放到同尺寸画布做参考图，与预览渲染算：

| 指标 | 含义 | cat 线稿实测 |
|---|---|---|
| `pearson` | 墨迹灰度图相关性 | **0.92**（预览线宽 4 时） |
| `ink_iou` | 二值墨迹交集/并集 | **0.75** |
| `src_ink` / `preview_ink` | 墨迹占比 | 4.2% / 3.3% |

`sketch` 模式在线稿上：pearson 0.73 / IoU 0.69（42 笔 / 492 顶点）；
`grid` 模式：164 个点（像素质感，不适合细节图）。

## 5. 图片先转成文字，再文字画（推荐路线，2026-10-18 晚补充）

手机上传页已经撤掉（价值不大，还多一个对外写文件的入口）。更顺的做法是
**任何能看图的模型/工具把图转成「坐标文字」，交给 `--from-plan` 直接画**：

```
python tools\draw-image.py --from-plan plan.txt               # 只规划出预览
python tools\draw-image.py --from-plan plan.txt --canvas 0,0,900,900 --draw
```

`plan.txt` 两种写法（`#` 注释、分号分隔多段、负数/小数都认）：

```
# 每行一条折线；数字按 x,y 两两配对
canvas: 24,24,976,976
100,100 300,100 300,300 100,300 100,100
450,650 600,650 600,700
500 300 520 300            # 空格也行
```

也可以直接喂本工具自己输出的 `plan-*.json`（里面有 `canvas_box` 就连画布位置一起用），
等于「先预览、后重放、再真画」。

## 5b. 字符画（ASCII art）→ 图 → 画（2026-10-18 上午补充）

用户拿到的常常不是图片，而是一段**字符画**（网页里 `<pre>` 一大段字符，或 .txt）。
这段文字本身就是图，`tools/ascii-to-image.py` 把它还原成 PNG 再走上面的流程：

```
python tools\ascii-to-image.py art.html                          # 还原 -> inbox\ascii-<时间>.png
python tools\ascii-to-image.py art.html --aspect 2.0 --map classic
python tools\draw-image.py "inbox\ascii-xxx.png" --mode sketch --draw
```

关键参数（都是踩过的坑）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--aspect` | 1.0 | 每个字符单元「高/宽」。字符画生成器通常按 2:1 显示补偿；`rows/cols ≈ H/W/2` 时用 2.0 |
| `--map` | coverage | `coverage` = 用真实等宽字体量每个字符的承墨量；`classic` = 按常见 70 级梯度序号（字符集是该梯度的子集时最准） |
| `--equalize` | 关 | 按承墨量排名均匀铺开对比度（不知道生成器用哪套梯度时更保险） |
| `--scale` | 2 | 每字符像素数；只用于看图/规划时可设 1 |
| `--invert` | 关 | 反相 |

判断 `--aspect` 的算术：字符画 `cols×rows`，若生成器做了 2:1 补偿，则
`rows ≈ H/W × cols ÷ 2`，反推原图高宽比 `H/W ≈ 2×rows/cols`。
实测样例：1000×1086 → 原图约 1080×2340（手机截图比例），故 `--aspect 2.0`。

## 5c. 照片 → 画：一键程序（2026-10-18 上午，响应「导入照片就能画」）

```powershell
# 双击仓库根的「照片转画.bat」= 小窗口：选照片 -> 质量 -> ①预览(不动鼠标) -> ②开始画
# 或者命令行：
python tools\photo-to-draw.py 照片.jpg                       # 只预览（安全）
python tools\photo-to-draw.py 照片.jpg --quality good --draw  # 真画
```

质量档位（`tools/photo-to-draw.py` 里的 PRESETS）：

| 档 | 等值线层数 | 精度 | 用途 |
|---|---|---|---|
| `quick` | 3 层（95/150/205） | 粗 | 30 秒-1 分钟，先看构图 |
| `good` | 5 层（90/125/160/195/225） | 中 | 默认，1-3 分钟 |
| `hd` | 7 层（70…220） | 细 | 3-8 分钟，细节最多 |

引擎是 `draw-image.py --mode engrave`：把灰度按多层阈值切层、逐层取轮廓线
（铜版画/等值线风格）。**为什么不用 sketch**：实测同一张 900 画布，
`sketch` 与原图灰度相关只有 0.18；`engrave` 4 层 0.67、5 层 0.68、墨迹重合 0.79。
画布越小越吃亏：482×483 白画布上 `engrave` 5 层只有 pearson 0.21-0.35
（线太细、覆盖不足），所以**画布大小是清晰度的第一瓶颈**。

**诚实边界**：板子只有 1 px 铅笔笔画，照片「无损」还原做不到（那是打印机/喷绘的活）。
能到的是钢笔/版画级还原：明暗层次 + 轮廓可辨认，细节取决于画布尺寸和笔画预算。
想要更接近照片只有三条路：放大画布（不最大化窗口）、加笔画（时间换质量）、
或者干脆把图交给打印机（不是"板子画"）。

程序结构：
- `tools/photo-to-draw.py`：CLI，套 presets 调 `draw-image.py`，输出计划/预览/相似度/真画结果
- `tools/photo-draw-gui.py`：tkinter 小窗口（选照片、质量下拉、预览、开始画、停止、日志）
- `照片转画.bat`：双击入口（优先 pythonw，无窗口）
