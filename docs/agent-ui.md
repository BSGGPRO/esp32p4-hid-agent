# 窗口版控制器 — 给人用的那份

> 这块 ESP32-P4 板子是一副**真的 USB 键盘鼠标**。它负责动手和看屏幕，这个窗口只负责发号施令——
> 板子是手和眼，界面只是遥控器。窗口里没有一行自己的执行逻辑，按下去的事全都交给
> `tools/connector.py` 干，和命令行版是同一套引擎。

**版本** 1.0.0 · 窗口标题「ESP32-P4 板子控制器 1.0.0」· 打包：`tools\build-ui.cmd` → `dist\esp32p4-agent-ui.exe`

---

## 0. 为什么双击命令行版会"闪退"

`esp32p4-agent.exe` 是**控制台程序，给 AI 用的**：它从 stdin 读作业、把 JSON 打到 stdout、退出。
人双击它的时候没带任何参数，它的行为是：

1. 打印一段用法（`--manual` / `--caps` / `--services` / `--selfcheck` / 作业）；
2. 再打一行「提示：没有作业输入。完整用法看 --manual」；
3. 以**退出码 2** 退出。

控制台窗口是它自己开的，程序一退窗口就关——看起来就是"闪退"。它没崩，只是**打完用法就退**。

| | `esp32p4-agent.exe`（命令行） | `esp32p4-agent-ui.exe`（窗口） |
|---|---|---|
| 给谁用 | AI / 脚本 | 人 |
| 怎么用 | `--manual` `--caps` `--services` `--selfcheck`，或把作业 JSON 从 stdin / 文件喂进去 | 双击开窗，点按钮 |
| 适合 | 批量作业、被别的程序调用、要输出到管道 | 手动点一下、把说明书交给别的 AI |
| 打包 | `tools\build-agent.cmd` | `tools\build-ui.cmd`（`--windowed`，没有控制台） |

两个 EXE 都是**产物、不进版本库**（`dist\` 在 `.gitignore` 里），要现打一个。

## 1. 窗口长什么样

深色窗口，**1080×820**（最小 960×700）。打开就是四块，从上往下：

1. **顶栏**：左边「板子控制器」+ 一行灰字说明，右边版本号；
2. **两张卡片并排**：
   - 左「**把说明书交给 AI**」：一个大按钮 `保存 AI 说明书…（下载）`（蓝色、主操作），
     下面一行小按钮 `复制说明书`、`给 AI 用…`；
   - 右「**检查**」：`自检`、`服务状态`、`看说明书`，卡片上写着"只看结论，不看代码"；
3. **「结果」卡片**（占窗口大头）：只会写人话。第一行是结论——
   `✓ 全体通过 —— 屏幕、认字、板子、指针、视觉五项都正常，现在就能用。`，
   下面每项一行 `✓`/`✗`，没过的那项直接给"怎么办"。运行的作业同理：
   `✓ 跑完了：1 步（ocr），共 1.5 秒。`，只读作业还会把读到的文字顺手贴几行出来；
4. **「用板子运行作业（JSON）」卡片**：左边作业输入框（默认填了
   `{"steps":[{"op":"title","exe":"msedge"}]}`），右边蓝色 `用板子运行`；
   下面一行 `复制详情（原始 JSON）`、`清空输出`。

**底部状态栏**：一个色点 + 一句话（● 绿=通过，● 黄=正在跑，● 红=没通过），比如
`五项自检：通过 —— 全都能用`。

**看不懂 JSON 是对的**：窗口里默认**不显示**任何 JSON。原始结果不会丢——
点「复制详情（原始 JSON）」就在剪贴板里，要发给人排错时再拿。

耗时按钮（自检、服务状态、运行作业）**在后台线程跑**，跑的时候窗口不卡，底部状态栏会显示
"…（在后台跑，界面不会卡）"。

**同一时刻只跑一个动作**：三个按钮共用一个"手"，跑起来时其余按钮变灰，
再点会提示"上一个动作还没结束"。这不是小气——同一时刻两个作业抢同一个串口会话，结果不可预期。
正在跑的时候关窗口，会先问一句"板子可能停在按键中间，确定退出？"。

## 2. 七个按钮

### ① 保存 AI 说明书…（下载） —— 最常用的那个

点一下 → 弹出「另存为」窗口，文件名已经填好 **`AI-控制器说明书.md`**，默认类型 `.md` →
选好位置点保存 → 得到一份 `.md` 文件。

- 写的是 **UTF-8 无 BOM、LF 换行**，Windows 记事本、VS Code、手机都能正常打开；
- 目录不存在会自动建；
- 存完输出框会写「已保存：<路径>（N 字节，UTF-8）」，并弹窗「保存好了」；
- 点取消 → 输出框写「已取消保存。」，什么都不发生；
- 保存不下来（没权限、路径非法）→ 弹窗「保存失败」并给出原因，**绝不假装成功**。

**存出来干什么？** 拖给别的 AI：

| 对方是什么 AI | 给它什么 |
|---|---|
| 能跑命令的（Codex、Claude Code、任何 agent） | 给它 `esp32p4-agent.exe`；它自己 `--manual` 就能看懂 |
| 只能读文字的（豆包、Gemini 网页版、任何聊天框） | 给它这份 `.md`；内容就是同一份说明书 |

拖进聊天框、或作为附件上传都行。**这份 `.md` 和仓库里的 `docs/ai-controller.md` 是同一份文件**，
EXE 里内嵌的也是它——所以给谁都一样，不会过期成两个版本。

### ② 复制说明书

把整份说明书塞进剪贴板（输出框会写复制了多少字符），直接 `Ctrl+V` 粘进聊天框。
适合"顺手问一句"；要长期用、或者怕聊天框截断长文，还是用①存成 `.md` 更稳
（剪贴板里的东西关掉窗口后可能被系统清掉，`.md` 是文件，不会）。

### ③ 自检

跑五项：**屏幕截取 / OCR 引擎 / 板子连接 / 指针校准 / 视觉服务**。

**输出是人话，不是 JSON**：

```
✓ 全部通过 —— 屏幕、认字、板子、指针、视觉五项都正常，现在就能用。
  屏幕截取　　   ✓  0.03 秒
  OCR 引擎　　   ✓  0.12 秒
  板子连接　　   ✓  0.01 秒
  指针校准　　   ✓
  视觉服务　　   ✓  0.00 秒
```

没过的时候第一行直接说哪项没过，末尾给一句"怎么办"：

```
✗ 没过：板子连接。
  ……
  · 板子连不上。两个 USB 口都要插（UART 给指令、高速 Type-C 给键鼠）；再点「服务状态」看 hub 和板子 TCP。
```

前三项是硬检查：不过就判"没过"；后两项只报告，不影响键鼠。**原始 JSON 还在**——
点「复制详情（原始 JSON）」，报错给人看的时就靠它。

### ④ 服务状态

三行（示例，以实际显示为准）：

```
hub        ✓ http://127.0.0.1:8765   串口 COM7 已打开
板子 TCP   ✓ 127.0.0.1:8766
视觉服务   ✗ http://127.0.0.1:8771   OCR 没加载· 大模型按需加载
```

下面还跟一句说明：**OCR / 找文字 / 读窗口 需要「视觉服务」；纯键鼠不需要**。
所以视觉服务那行是 `✗` 时，鼠标键盘照样能动，只是自检里的「OCR 引擎」多半也是 `✗`，
作业里 `ocr` / `find` / `ui` / `see` 会直接报错（"没有可用的 OCR：视觉服务（8771）没在跑"）。

### ⑤ 看说明书

在窗口里开一个只读子窗口，标题是「AI 说明书（N 行）」，内容就是①存出来的那份。
不用离开程序就能查规矩、照着抄一段作业 JSON。

### ⑥ 用板子运行（运行作业）

左下的框里粘一段作业 JSON（默认示例是读 Edge 窗口标题），点「用板子运行」：

- 空框 → 输出框提示"还没有作业内容"，并给一个能直接用的例子；
- JSON 写错 → 输出框写「这不是合法的 JSON：第 N 行第 M 列，<原因>」，不会崩；
- JSON 合法但不是对象/数组（比如 `123`、`"abc"`）→ 提示作业应该是 `{"steps": [...]}` 或 `[...]`；
- 每一步缺 `op`（比如 `[1,2]`）→ 提示"每一步都得是带 op 的对象"，不会掉进底层报 `AttributeError`；
- 作业里一个步骤都没有（`[]` 或 `{"steps": []}`）→ 提示"作业里没有步骤（什么都没做）"，
  不会给你一个绿色的"完成"骗你以为跑了；
- 跑起来 → 输出框只写一句人话：`✓ 跑完了：1 步（ocr），共 1.5 秒。` 或
  `✗ 没跑成：第 2 步 click 失败：坐标越界`。只读作业（`ocr` / `read_text`）还会把读到的文字
  贴几行出来——那几行就是你要回给聊天 AI 的内容。完整 JSON 点「复制详情（原始 JSON）」拿。

> ⚠️ 这个按钮**不是预览**：按下去板子会真的移动鼠标、真的敲键盘。跑之前先看清楚作业内容。

旁边两个小按钮：「复制详情（原始 JSON）」把上一次的原始结果放进剪贴板；
「清空输出」只清结果区，不碰作业框。

### ⑦ 给 AI 用…

把控制器交给别的 AI 的地方。点开后是一个 820×620 的子窗口（不会最大化、不抢别的程序）：

1. 下拉选一个 AI：Claude Code / Gemini CLI / VS Code Copilot / Windsurf / Cline / Codex / Cursor / 豆包；
2. 中间只读框显示**给这个 AI 的那一段**——MCP 类是一段能直接粘进配置的 JSON（路径按当前实际位置生成），
   命令类是中文指令（让它读 `AGENTS.md`、跑 `python tools/connector.py`），聊天类是"把说明书拖进去"；
3. 「复制这段」塞剪贴板，「保存成文件」存成 `.json` / `.txt`（UTF-8 无 BOM）。

⚠️ 一个实情：**MCP 那段需要一个真实的仓库**（`tools/mcp_server.py` 得在）。如果你只是把 EXE 单独拷到桌面、
旁边没有仓库，这一段会直接告诉你"身边没有仓库"，并给出两条替代办法——它不会给你一个假的临时路径
（打包解压目录退出就删，那种配置粘过去必然连不上）。

哪个 AI 属于哪一类、依据是什么，见 [docs/ai-compat.md](ai-compat.md)。

## 3. 出错怎么办

| 现象 | 先看哪 | 怎么办 |
|---|---|---|
| **窗口没出来**（双击没反应 / 一闪就没了） | 是不是弹了「启动失败」弹窗？弹窗里有日志路径 | 打开崩溃日志 `agent-ui-error.log`（在 EXE 旁边；写不进去就在 `%TEMP%`）。单文件 EXE 每次启动要自解压，第一次会慢一两秒，别连点好几下 |
| **点按钮没反应 / 弹了个「出错了」框** | 框里写着异常类型和日志路径 | 那是按钮里真出错了（不是卡住）。日志里那一节有完整堆栈；窗口**不会**因此退出，别的按钮照样能用 |
| 提示 **视觉服务没在跑** / 服务状态里那行是 `✗` | 只影响读字、找文字、读窗口 | 跑 `python tools\visiond.py --start`；或者不管它——第一次 `ocr` / `see` 会自动拉起（第一次要等 OCR 引擎加载）。纯键鼠不需要它 |
| 提示 **板子连不上** | 点「服务状态」：hub、板子 TCP 两行 | 两个 USB 口**都要插**：UART（CH340）给指令，高速 Type-C 给键鼠。`127.0.0.1:8766` 通就不用起 hub；不通会自动直连串口。串口被别的程序占着会报 `board_busy`——一次只能一个客户端 |
| **保存失败**（没权限 / 路径不对） | 弹窗里那句 Windows 原话 | 别存 `C:\Windows`、`Program Files` 这类要管理员的地方；换桌面或「文档」。目录会自己建，不用手建 |
| **杀毒软件拦截** | 是不是被杀软弹了"已阻止" | 单文件 EXE 是自解压的，常被误报。确认来源（自己打的或从仓库拿的）后允许运行 / 加白名单；别从压缩包里直接双击，先解出来 |

补一句：EXE 每次启动都要自解压到临时目录。如果日志里是 `Could not create temporary directory`，
说明那个目录不让写临时文件——把 EXE 挪到普通文件夹（比如桌面）再双击。

还想确认"EXE 本身有没有坏"：命令行里跑 `esp32p4-agent-ui.exe --selftest`（或先 `set AGENT_UI_SELFTEST=1`
再运行），它不开窗口、只跑一遍关键路径（说明书能不能读、能不能存、窗口能不能建、26 个操作在不在），
结果写进 `%TEMP%\agent-ui-selftest.json`，全通过退出码 0。窗口版没有控制台，所以看文件、别看屏幕。

## 4. 红线

**禁止改固件。** `firmware/` 是只读的：不许编译、不许烧录、不许改任何 `.c` / `.h` /
`sdkconfig` / `partitions.csv`。要改先停下来问人——固件已经在板子上跑着，乱动等于把这台机器的
"手"弄断。这条规矩写在说明书第一页，也写在 [operations.md](operations.md) 里。

其余几条同样适用于这个窗口：不动用户窗口（不最大化、不移动）、全屏应用不发键鼠、
不可逆动作（删除/发送/支付/关机）先问人、别猜坐标。窗口只是把作业递给连接器，
**它不会替这些规矩兜底**。
