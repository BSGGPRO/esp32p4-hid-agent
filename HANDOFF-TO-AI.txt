 第一部分 · 这是什么
================================================================================
一块真实的 ESP32-P4 开发板（JC-ESP32P4-M3-DEV，16 MB Flash / 32 MB PSRAM）插在这台
Windows 上，通过 USB 枚举成「键盘 + 鼠标」复合 HID 设备（VID 0x303A / PID 0x4004），
所以它等于一双电子手。

数据通路（单向示意）：
  AI/脚本  ->  pc/brain.py（动作层）
          ->  TCP 127.0.0.1:8766（hub 的串口透传）
          ->  hub（pc/hub.py，常驻，独占 COM7，同时跑网页 8765）
          ->  板子 UART0 / CH340 COM7 @115200，一行一个 JSON
          ->  板子固件执行 -> USB HID 报文 -> 这台 Windows 的光标/键盘
  反馈：GetCursorPos() / 截屏（pc/eyes.py）闭环，所以能精确到像素级落点。

三块组成：
  firmware/   ESP-IDF 固件（v1.2.0），USB HID 键盘鼠标 + UART JSON 协议 + TF 卡/温度/PM
  pc/         PC 侧：hub（网页+串口）、brain（动作层/闭环定位）、eyes（截屏）、verify（差分）
  web/        网页仪表盘（只读板子状态 + DFS 开关），由 hub 在 8765 提供
  tools/      标定、绘图、板子锁、自检等工具
  docs/       协议/硬件/网页/指针标定等文档（本文件末尾有索引）

 第四部分 · 第一步：自检 5 条命令（粘贴到 cmd，逐条看结果）
================================================================================
cd /d %USERPROFILE%\Documents\deepseek-harness\default-workspace\esp32p4-hid-agent
set PY=%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe

:: 1) 板子活着 + 屏幕/光标
%PY% pc\brain.py --transport tcp --json info
:: 2) 截屏（生成 pc\shot.png，2560x1440）—— 能看图的你从这里"睁眼"
%PY% pc\brain.py --transport tcp --json look
:: 3) 列窗口（找"画图"或目标窗口，含 rect/前台/最小化）
%PY% pc\brain.py --transport tcp --json wins
:: 4) 把光标移到绝对坐标（闭环，误差约 1 px）
%PY% pc\brain.py --transport tcp --json point 640 360
:: 5) 再确认状态（确保没有按住的键）
%PY% pc\brain.py --transport tcp --json info

成功标志
  · 每条 JSON 里 "ok": true；info 里有 "port": "COM7"、"screen": [2560,1440]、"cursor": [x,y]
  · look 返回 "shot" 路径，文件存在（约 1 MB，2560x1440）
  · wins 返回窗口数组，能看到 "画图" 之类标题

失败对照
  WinError 5 / 端口被占用        -> 忘了 --transport tcp
  board_busy / 板子锁被占用      -> 有别的进程占用串口；等最多 1 分钟（看门狗会恢复）
  tcp 连接被拒                   -> hub 没在跑；检查 http://127.0.0.1:8765/api/health
  argparse: unrecognized --json  -> --json 是全局参数，必须放在子命令前面：
                                    正确: brain.py --transport tcp --json info
                                    错误: brain.py --transport tcp info --json

 第五部分 · 动作接口（pc\brain.py 子命令 / run 的 op）
================================================================================
look                        截屏 + 光标/前台窗口/窗口列表；写 pc\shot.png（可 --region x,y,w,h）
point X Y [--tol 2]         绝对定位，闭环收敛
locate X Y [--tol 1]        绝对定位，1px 容差 + 抗用户打断（推荐画图用）
move DX DY                  相对移动（DY 正 = 向下）
click [X Y] [--button left|right|middle] [--count N]
drag X1 Y1 X2 Y2            定位->按下->定位->抬起（中间无线）
drag-path "X1,Y1;X2,Y2;..." 一次按下-连续移动-抬起（画线条必须用这个）
scroll AMOUNT               滚轮，正 = 向上
type "text" [--cps 40]      逐字符打字（仅 ASCII 0x20-0x7E，中文打不出来）
key ctrl+s                  组合键（按下->30ms->全部抬起）
tap enter                   单击一个键
wins                        可见窗口列表（hwnd/title/pid/rect/foreground/minimized）
focus "画图"                按标题子串切到前台
read-text                   用 ctrl+a / ctrl+c 读前台窗口文字（会覆盖剪贴板，默认恢复）
clip get | clip set "..."   读写剪贴板
launch CMD                  启动本机进程（不走 HID）
info                        板子状态 + 屏幕 + 光标

说明
  · brain.py 每次动作结束都会 release_all，脚本中断/异常也会释放，不会卡住键。
  · 不要自己算"发多少 step 能到目标"：Windows 指针加速是非线性的，直接 point/locate。
  · type 只支持 ASCII；要输入中文请用 clip set + key ctrl+v。

 第六部分 · 批量脚本（画画强烈推荐：一次连接跑完，比逐条命令快约 10 倍）
================================================================================
%PY% pc\brain.py --transport tcp run --script plan.json

plan.json 是一个动作数组。完整示例（开画图、画 200x200 方框、截图差分验证）：
[
  {"op":"launch","cmd":"mspaint"},
  {"op":"sleep","ms":1200},
  {"op":"focus","title":"画图"},
  {"op":"look","path":"before.png"},
  {"op":"drag_path","button":"left",
   "points":[[300,300],[500,300],[500,500],[300,500],[300,300]]},
  {"op":"look","path":"after.png"},
  {"op":"diff","a":"before.png","b":"after.png"}
]

可用 op（参数即 JSON 字段名）
  look        : path?, region?
  point       : x, y, tol?
  locate      : x, y, tol?
  move        : dx, dy
  click       : x?, y?, button?, count?
  drag        : x1, y1, x2, y2, button?
  drag_path   : points=[[x,y],...], button?, guard?（默认 true，用户抢鼠标就重新锚定）
  scroll      : amount
  type        : text, cps?
  key         : combo
  tap         : key, hold_ms?
  hold        : keys=[...]        release : （无参数，全抬）
  sleep       : ms?
  wins        : （无参数）
  focus       : title
  launch      : cmd
  clip_get / clip_set : （无参数 / text）
  read_text   : select_all?, restore_clip?
  diff        : a, b, threshold?
  wait_change : timeout_ms?, interval_ms?, threshold?
  info        : （无参数）
  stop        : （无参数，中止后续步骤）

默认某步失败就中止；加 --keep-going 继续。

 第七部分 · 画图标准流程（照做，别自由发挥）
================================================================================
1) look 截图 -> 你自己看图，量出画布矩形（不要把窗口最大化）
2) wins 找"画图" -> focus "画图"（不要改窗口大小/位置/层级）
3) 在截图上规划折线：一笔 = 一串点
     · 直线：两端点即可
     · 圆弧/曲线：每 4-8 px 打一个点（点太稀会变成折线，太密速度慢）
     · 圆：参数方程多点采样，间距按周长/点数算
4) 写成 plan.json -> run --script plan.json 执行
5) 再 look 一次 -> 自己看图检查；必要时 diff 做像素差分
6) 汇报：画了几笔、耗时、落点误差、哪里不理想

现成参考实现（复杂图、窗口检测、防遮挡、线宽自适应、离屏几何校验）：
  tools\draw-rage.py --detect   只检测窗口/画布，不动笔
  tools\draw-rage.py --plan     只打印笔画坐标，不动笔
  tools\draw-rage.py --mock     离屏渲染校验几何，无副作用
  tools\draw-rage.py            真画（--no-move 表示即使和聊天窗口重叠也不移动窗口）

画图经验
  · 线条必须用 drag-path（一次按下连续移动）；用 drag 画出来是断开的。
  · 大范围移动前先 locate 到起点附近，再按下，能明显减少起笔偏差。
  · 复杂图案先画外轮廓再画细节；颜色/粗细切换要点工具栏按钮，按钮位置先用 look 量。
  · 画完一定要 look 复核；用户可能正看着屏幕。

 第八部分 · 精度与换设备标定
================================================================================
· 相对鼠标 + GetCursorPos 闭环，落点误差实测约 1 px（2560x1440 @125%）。
  实测证据：5 个验收点（四角内缩 + 屏幕中心）最大误差 1 px；CNC 式四角撞边
  停在 (0,0)/(2559,0)/(2559,1439)/(0,1439)，反推桌面 2560x1440 与系统 API 一致。
· 不要开环算步数；用 point / locate / drag_path 让 brain 收敛。
· 换电脑/分辨率/缩放开画之前，先跑一次（约 10 秒，会短暂占用鼠标）：
    %PY% tools\home-calibrate.py --transport tcp --apply
  原理：屏幕四边 = 硬限位，撞四角得到绝对参考和屏幕尺寸，再在屏幕中心重测
  count->px 增益（Windows 指针加速曲线），结果按"分辨率|虚拟桌面|DPI模式"存进
  C:\ProgramData\dsh\pointer-profile.json。之后 brain 启动时自动应用（无需再标定）。
· 查看档案：%PY% pc\pointer_profile.py status

 第十一部分 · 板子 / 固件 / 协议事实（接手排障用）
================================================================================
硬件
  · 芯片 ESP32-P4（本板实测 rev v1.3 早期硅片，编译配置
    CONFIG_ESP32P4_SELECTS_REV_LESS_V3=y，因此 CPU 只有 40 / 360 MHz 两档）
  · 16 MB Flash（QIO 80 MHz，app 分区 3 MB @0x10000，分区表 @0x8000）
  · 32 MB PSRAM（实测 33554432 B 可用）
  · USB：设备模式 HS，专用 USB_DM/DP 引脚；VID 0x303A / PID 0x4004，
    字符串 "JC-ESP32P4-M3 Agent" / "P4 HID Bridge"，Serial = 芯片 MAC
  · UART0：GPIO37 TXD / GPIO38 RXD -> CH340C -> COM7，115200 8N1
  · TF 卡槽：microSD，4bit/20MHz，无独立 CD 引脚（cd 字段恒 null）
  · 接口：板上有多个 Type-C —— 烧录/协议走「转 UART 口」（CH340 -> COM7），
    HID 设备走 P4 原生 USB 2.0 HS OTG 口（VID_303A / PID_4004）；两个口都要插才有"手"。
    具体丝印归属以原理图为准（本文件不推断左右位置）。
  · 供电要求 ≥ 500 mA @5V；不要碰 GPIO 7,8 / 9-13 / 48 / 21 / 35,36 / 14-19,54 / 24-27

固件 v1.2.0 能力
  · HID 键盘（Report ID 1，boot 8 字节）+ 鼠标（Report ID 2，5 字节）
  · 鼠标相对移动，单报 |dx,dy,| <= 127，超出自动拆多帧；EP IN 0x81 / 16 B / bInterval 4
    （HS 1 ms/帧、FS 4 ms/帧）
  · 安全释放：默认 1500 ms 无任何 PC 报文 -> 强制 release_all + safety_release 事件
  · 统计：stats（CPU 双核占用/频率/内存/PSRAM/温度/任务栈/HS 栈水位/TF 卡/UART/HID/PM）
  · TF 卡：sd_test（1 MB 读写校验测速）、sd_remount（免重启换卡）、sd_format（破坏性，
    需 confirm:"ERASE"）
  · 省电调度 PM：默认 fixed360（固定 360 MHz）；dfs=1 时为 adaptive（40-360 MHz，
    带锁提升与 500 ms 迟滞）；measured_mhz 是独立测得的物理频率证据。
    ★ 该开关不写 NVS：重启后回到默认 fixed360。
  · 温度：temp_c / temp_warn（默认 70 °C 告警），支持 set temp_warn_c / temp_throttle_c

协议（UART JSON-lines，proto 1.2）
  · 请求：{"cmd":"<name>","id":<int 可选>,...}；带 id 必须回同 id 响应；
    不带 id = fire-and-forget
  · 响应：{"ok":true|false,"id":N,...}；失败带 "err"
  · 事件：{"evt":"hid_mounted|hid_unmounted|safety_release|boot",...}
  · 所有响应/事件带 "t"（开机毫秒）；未知字段必须忽略；未知 cmd -> err:"unknown_cmd"
  · 帧：一行一个 JSON，请求 <=512 字节；stats 响应约 1.5 KB（PC 侧行缓冲 >=4096）
  · 命令表：ping / status / keepalive / set(key,value) / stats / sd_test(bytes?)
    / key(keys[]) / key_tap(keys[],hold_ms?) / key_down / key_up / release_all
    / text(text,cps?) / mouse_move(dx,dy) / mouse_btn(btn,action) / mouse_scroll(dy)
    / mouse_click(btn?,count?,interval_ms?) / sd_remount / sd_format(confirm,fs?)
  · set 的 key：safety_timeout_ms(0-60000) / temp_warn_c / temp_throttle_c / dfs(0|1)
  · 错误码：bad_json / unknown_cmd / bad_arg / bad_key / unsupported_char /
    not_mounted / rate_limited
  · 限流 200 条/秒（固定窗口）；release_all 永远免限流（安全优先）
  · 键名：修饰键 leftctrl/leftshift/leftalt/leftgui(=win/cmd/meta/super)/右侧同名；
    普通键 a-z 1-9 0 enter esc backspace tab space minus equal leftbracket
    rightbracket backslash semicolon quote grave comma period slash capslock f1-f12
    printscreen scrolllock pause insert home pageup delete end pagedown
    right left down up numlock kp_* application power
  · 实测性能（真板）：ping 往返 18.4 ms；mouse_move ack 12.5 ms；dx=1000 拆 8 帧
    19.6 ms；连发 332 条/秒；安全释放 2.2 s 静默后按键已抬起

 第十四部分 · 用户发图片给你，怎么画出来
================================================================================
【先说清楚】这条链路不需要"模型看图"：图片 -> 笔画是确定性图像算法
（阈值/细化/追踪/简化），你只要能跑命令就能画。判断画得像不像用数值指标，
最后像不像让用户（或能看图的模型）拍板。

【Step 1 收图】三种入口，任意格式（png/jpg/jpeg/webp/bmp/gif/tif/tiff/svg，
  手机 HEIC 先在相册里导出 JPG）：
  a) 用户把文件放电脑上 -> 记住路径
  b) 用户复制了一张图（截图/网页图）-> python tools\ingest-image.py --clipboard
  c) 手机传：浏览器打开 http://<PC-IP>:8765/upload 拍照/选图，落盘到
     <workspace>\inbox\，然后 python tools\ingest-image.py <那个路径> --thumb 1200
  ingest-image.py 输出一行 JSON：{"ok":true,"path":"...png","size":[w,h],"thumb":...}

【Step 2 规划（不碰鼠标）】
  python tools\draw-image.py "<图>" --mode line   --canvas 0,0,1000,1000 --preview-width 4
  python tools\draw-image.py "<图>" --mode sketch --edge 40
  python tools\draw-image.py "<图>" --mode grid   --cell 10 --canvas 0,0,600,600
  输出：strokes 笔数、vertices 顶点数、est_seconds 预估秒数、
        similarity{pearson, ink_iou} 像不像的数值，以及
        inbox\plan-*-preview.png（预览图，可以给能看图的模型或用户看）
  经验：line 适合线稿/卡通/logo（pearson>0.9 算好）；sketch 适合照片（速写风）；
        grid 只适合小图标。

【Step 3 真画】把 --canvas 换成自动检测（先打开画图、别最大化），加 --draw：
  python tools\draw-image.py "<图>" --mode line --preview-width 4 --draw
  它会自己：找画图窗口 -> 检测白色画布 -> 复核前台是画图 -> 逐笔闭环起笔 +
  按实测增益表快速推进 + 每 8 个顶点闭环校正 -> 结束 release_all -> 截图算墨迹。
  用户抢鼠标（偏差>40px）会抬笔跳过该笔并记录，不会把他的乱动画进去。

【速度】26 笔/193 顶点约 4 秒；42 笔/492 顶点约 7 秒。上千顶点先跑预览看
  est_seconds，超过 60 秒建议减笔画（--min-len 8 --simplify 2 或 max-strokes）。

【安全】默认只规划不落笔（--draw 才动鼠标）；不改画图窗口大小/位置（绝不最大化）；
  每笔前复核前台窗口；结束一定 release_all。

 附录 · 十个高频问答
================================================================================
Q1 我能直接用 HTTP 接口画画吗？           不能。POST /api/cmd 的 mouse_move 被限制
                                          为 dx=dy=0；画画必须本地跑 brain.py --transport tcp。
Q2 为什么不用 agent_bridge.py 画画？      它走 uart 直连，需要板子锁；hub 占着串口。
                                          调试单条协议命令可以用它，但 hub 在跑时用不了。
Q3 一次能画多少笔？                       一个 plan.json 里几十~几百步都行（一次连接），
                                          但建议分批：每 20-40 笔 look 一次复核。
Q4 画图偏了几像素怎么办？                 先用 look 量画布真实边界，起点用 locate 精确落位；
                                          画笔有宽度，线宽大时坐标按半宽内缩。
Q5 用户的鼠标动了怎么办？                 brain 的 guard 会检测到用户介入，重新锚定而不是硬拽；
                                          drag_path 时有 guard 参数（默认开）。
Q6 会把我按住的键卡住吗？                 不会：每条命令结束 release_all；固件还有 1500 ms
                                          安全释放兜底。
Q7 板子会过热吗？                         当前 28.6 °C，阈值 70 °C 告警；PM 有温度联锁。
Q8 想改板子固件/网页怎么办？              不要改。两者已验证无已知问题，是工具不是待修项目。
Q9 换一台电脑（比如 1080p）要做什么？     跑一次 tools\home-calibrate.py --transport tcp --apply
                                          （10 秒），之后自动适配。
Q10 板子灯/重启/拔插会怎样？              重开会重启板子（CH340 DTR/RTS 行为），等 2 s 后
                                          hub 自动重连；/api/board 会短暂 ok=false，正常。
